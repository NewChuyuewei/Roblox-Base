## 1. 与标准目标的关系（诚实版）

`PSAC.md` §4 已说明：标准原文不在手边，故**行级目标矩阵尚未建立**。本文件做的是：把「DAL C 需要的验证结论」转成本项目**可执行、可判真假**的 5 条判据，并逐条映射到 Annex A 的**表**（表级，来源已核实）。

| 本项目的验证判据 | 映射到 | 对应活动（已核实的引用） |
| --- | --- | --- |
| **V-1** 需求可验证且一致 | A-3 · A-1 | 需求评审；`REQ-STD.md` §4 |
| **V-2** 代码符合 LLR 与架构、且可验证 | A-4 · A-5 | 源码审查（Adacore 记 A-5[1..3] 即"源码符合 LLR / 符合架构 / 可验证"） |
| **V-3** 每条 HLR/LLR 被至少一个用例覆盖 | A-7（obj 3/4：HLR、LLR 覆盖） | 需求驱动测试；`TRACE.md` |
| **V-4** 结构覆盖达 **statement**，未覆盖行有解释 | A-7（6.4.4.2；**C 级只需 statement**） | 覆盖工具（C4） |
| **V-5** 测试程序与结果正确、差异已解释 | A-7（obj 1/2） | 测试评审 + 结果归档 |

**明确不做的**（写出来，避免被当成遗漏）：MC/DC 与 decision 覆盖（C 级不要求，且本生态无工具）、对象码级验证（DV-4）、目标码可追溯性（DV-2）、独立性组织保障（DV-1）。

## 2. 验证方法（四类，各自的用途）

| 方法 | 用于 | 产物 |
| --- | --- | --- |
| **评审（Review）** | 需求、设计、代码、测试程序 | `docs/cert/verify/*.md` 的评审记录；发现进 `PROBLEMS.md` |
| **分析（Analysis）** | 追溯完整性、覆盖缺口、类型/转换一致性 | `TRACE.md`（CI 生成）· 覆盖报告 |
| **测试（Test）** | V-3/V-4 的主要手段 | 用例 + 结果（可复现命令） |
| **故障注入（Fault injection）** | H4/H5 的场景：崩溃点、超时、配额、写失败 | 注入脚本 + 结果；**属需求的一部分**，不是附加测试 |

## 3. 需求驱动测试（V-3）

| 规则 | 说明 |
| --- | --- |
| 用例必须绑需求 | 用例 ID 形如 `TC-<MOD>-nnn`，文件头声明 `-- covers: LLR-X-nnn, HLR-X-nnn` |
| 三类用例齐备 | 正常 / 边界 / 错误——缺任何一类则该需求视为未覆盖 |
| 边界要有依据 | 数值边界必须来自 `TYPES.md` §3 的声明（如整数精度 2^53），不是随手取的数 |
| 负面用例是常态 | 尤其是安全相关：RLS 谓词、唯一约束、锁顺序（I15） |
| 测试不得依赖未验证的东西 | 底座只能是 `SimulatorPort` + 受控 Luau（I19） |

## 4. 结构覆盖（V-4）

| 项 | 规定 |
| --- | --- |
| 目标 | **100% statement**（DAL C）；未覆盖行必须给出解释或开问题报告 |
| 工具 | `scripts/coverage.luau`（C4 交付，自研） |
| **前置探针** | **先做 `debug.sethook` 在 Lune 0.11.1 的可用性探针**；不可用则 V-4 无法关闭，`DAL C` 本身需重新评估（`CERT.md` 末尾未决项、风险 R18） |
| 工具的信任度 | 自研工具的输出**不得单独**作为关闭证据：需辅以对该工具本身的评估（`CERT.md` §4.4） |
| 与其他测试的关系 | 结构覆盖是 **requirements-based 测试的副产品**，不额外造测试来凑覆盖（DO-178C 的原意：覆盖是**检验测试充分性**，不是替代测试） |

## 5. 环境与可复现性

| 项 | 规定 |
| --- | --- |
| 底座 | `SimulatorPort`（确定性、内存、可注入故障）+ 固定版本 Lune |
| 复现 | 每个用例给出一条命令；CI 用同一条命令 |
| 网络 | **禁止**（`docs/cert/` 的任何证据不得依赖网络） |
| 报告分流 | `docs/cert/` 只放认证证据；产品线测试报告（含 `SelfTest`）**分开存放，不得合并**（`CERT.md` §9.2） |
| 时间/随机 | 用例不得依赖墙钟或随机；需要时用注入的确定性时钟（`TaskScheduler.Update(now)` 已为此设计） |

## 6. 独立性（DV-1，永久偏差）

| 做法 | 说明 |
| --- | --- |
| 独立会话 | 验证/评审由**不共享上下文**的另一会话执行并留证（本项目已有先例：Step 3 的独立复审子代理） |
| 不同角色 | 实现者不得复核自己的产物通过 |
| **不声称** | 这不是组织独立性。真实 DER 不会接受其等同 —— 作为 DV-1 永久记录 |
