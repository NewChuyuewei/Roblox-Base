# 类型与转换规约

> C2 交付，CC1。**存在理由**：DO-178C §6.7/6.7.1 要求**一致地使用类型**并**说明类型之间的转换意图**。动态类型语言（Luau）默认不满足这一条 —— DLR 关于航空 Lua 的研究明确指出这一点，他们的结论是必须把隐式转换显式标记并把意图写出来（`CERT.md` §0 根因 3）。
> 上游：`REQ-STD.md` §4 R7（数值依据）。

---

## 1. 规约的三条硬规则

| # | 规则 | 为什么 |
| --- | --- | --- |
| **T1** | 认证范围内每个数据项只有**一个声明类型**，写在 §2 的表里 | 「一致使用类型」的可检查形式；不允许同一个值在不同模块被当不同类型用 |
| **T2** | **禁止依赖隐式转换**：需要转换时写显式函数，并把"为什么这个转换是安全的"写进注释或 LLR | 隐式转换是动态语言最常见的静默失效来源；DO-178C 要求说明转换意图 |
| **T3** | 数值边界必须有**显式断言**，且边界值来自 §3 的推导而非随手写 | 边界是需求（`REQ-STD.md` R7），不是实现细节 |

## 2. 认证范围数据项的声明类型

| 数据项 | 声明类型 | 值域 / 约束 | 禁止 |
| --- | --- | --- | --- |
| `key`（存储键） | `string` | `#key ≤ 50`（`SCALE.md` §1.3 已核实的硬限） | 禁隐式 `tostring(number)` 作为键 |
| `rowId` / `pageId` / `txnId` | `string`（编码后） | 由 `NamespaceCodec` 产生 | 禁直接用 number |
| `lsn` | `number`（整数） | `0 ≤ lsn < 2^53`（见 §3） | 禁浮点运算/非整数赋值 |
| `partition` | `number`（整数） | `0 ≤ p < 2^31` | —— |
| `slotId` | `number`（整数） | `≥ 1`（0 保留为"空槽"） | 禁用 0 表示有效槽 |
| `boolean` 字段 | `boolean` | 只有 `true`/`false` | 禁 `nil` 表示 false（§4 H1） |
| `optional` 值 | `T?` → 显式 `nil` 检查 | —— | 禁 `if x then` 直接当布尔用（§4 H1） |
| `DECIMAL/SQL NUMERIC(p,s)` | `{ int: number(整数), scale: number(整数) }` | 见 §3 推导 | **禁** 用浮点表示金额/计数 |
| `TIMESTAMP` | `number`（Unix ms，整数） | `≥ 0` | 禁用秒 |
| `JSON` 列 | `table`（受控形状） | 深度 ≤ §3 的 `MAX_JSON_DEPTH` | 禁把任意用户表直接当 JSON 存 |
| 表/数组 | `{ T }`，**无洞**（`1..#t` 连续） | —— | 禁 `#t` 用在有洞的表上（§4 H2） |

**类型声明写在需求里**：每个数据项首次出现时，HLR 或 LLR 必须写出上表对应的类型与约束。

## 3. 数值边界（推导，不是随手写）

Luau 的 `number` 是 IEEE-754 **双精度**：整数**精确**范围是 `±2^53`（9,007,199,254,740,992）。越过它之后 `n+1 == n` 会成立 —— 在 `lsn` 或金额上这是静默数据损坏。

| 边界 | 值 | 推导 |
| --- | --- | --- |
| `lsn` 上限 | `2^53` | 精确整数上限；超出必须先报警再考虑分段 |
| `INT` | `±2^31` | 与主流 RDBMS 一致；便于与外部交换 |
| `BIGINT` | `±2^53` ← **不是 2^63** | **Luau 装不下 2^63 的精确整数**：这是本项目 `BIGINT` 与 SQL 语义的**已知偏差**，必须在文档与错误信息里说明，禁止假装它是 64 位 |
| `DECIMAL(p,s)` | `p - s ≤ 15` 位整数部分 | 由 2^53 ≈ 9.0e15 推得的安全上限 |
| `MAX_JSON_DEPTH` | 8 | 与 `StructuredLog` 的渲染深度意图一致；也是防递归爆炸的边界 |
| `PAGE_BYTES` | 4096（目标） | `SCALE.md` §1.3：单值 4 MiB − 序列化余量 |
| `ROW_OVERHEAD` | 由 `HeapLayout` 声明 | 页满判定用（`LLR-PAGEMGR-007` 引用它） |

**每条边界都要有测试**：`V-3` 的"边界用例"指的就是这些值（及 `值±1`）。

## 4. 动态类型的已知危险（逐条给出规避规约）

| # | 危险 | 例子 | 规约 |
| --- | --- | --- | --- |
| **H1** | `nil` 与 `false` 都被当假 | `if slot.deleted then` → `nil`（缺失）与 `false`（未删除）不可区分 | 布尔字段**必须**显式初始化为 `false`；判定用 `== true` / `== false`；可选值用 `== nil` |
| **H2** | `#t` 对有洞的表不可靠 | 先 `t[3]=x` 再 `#t` 可能是 0 | 认证范围内数组**只 append，不按索引乱写**；删除用软删除标记（与 `Tri.Storage` 的软删除一致） |
| **H3** | 字符串/数字隐式转换 | `"1" + 1 == 2`；`0 == "0"` 为假 | 禁止把外部输入直接参与算术；入口处显式转换并校验（I17） |
| **H4** | 表的形状漂移 | 同一字段有时是 number 有时是 string | §2 声明类型；边界处校验形状；转换集中在 `Tri.Types` |
| **H5** | 元表/`__index` 改变行为 | 序列化时 `pairs` 只遍历原始字段，`__index` 提供的字段会丢 | 认证范围**禁止在数据载体上设元表**；需要行为时用显式函数 |
| **H6** | 浮点比较 | `0.1 + 0.2 ~= 0.3` | 金额/计数一律整数（§2 的 `NUMERIC` 表示）；浮点只用于统计量，且比较用显式容差 |
| **H7** | 整除法/取模对负数的语义 | `-7 % 3` 在 Luau 为 2（floor 语义） | 凡用 `%`/`//` 的分区与哈希，LLR 必须写明负数行为并测 |
| **H8** | `table.sort` 的比较器不一致 | 比较器返回 `a <= b` 会导致顺序不确定 | 比较器必须是**严格弱序**；键排序用统一比较器函数 |

## 5. 认证范围的禁止清单

| 禁止 | 理由 |
| --- | --- |
| `loadstring` / `load` | 动态求值使代码不可静态追溯（门禁 10 A 段已拦 `loadstring(`） |
| `getmetatable`/`setmetatable` 用于数据载体 | H5 |
| `pcall` 用作流程控制（而非错误边界） | 会掩盖错误路径，使 LLR 无法映射 |
| 依赖 `#t` 与 `pairs` 顺序 | 迭代顺序未定义，会让测试结果不可复现 |
| 隐式 `tostring` 作为持久化键 | §2 |
| 在认证核心内 `os.time()` 直接取时间 | 破坏确定性（I19）：时间必须**注入**（`TaskScheduler.Update(now)` 的既有模式） |

## 6. 评审检查单（并入 `SDP.md` §6 第 5 条）

1. 每个数据项能在 §2 找到声明类型吗？
2. 每个转换是显式的、且有安全性说明吗？
3. 数值边界有断言，且值来自 §3 吗？
4. H1–H8 相关的代码路径有用例吗（尤其 H1 的 `nil`/`false`、H2 的有洞表、H7 的负数取模）？
5. 有时间/随机依赖吗（应为注入）？
