# Carbon 执行计划：Phase 与 Wave

> 总图是 `.plan/CARBON.md`，组件的功能块在 `.plan/COMPONENTS.md`；本文件回答「**按什么顺序做、每一步做完的标志是什么**」。
> 这是 Carbon 的唯一排期。总图里原来的阶段 `S0–S6` 与步骤 `C1.1–C2.7` 都并入这里（对照见文末）。
>
> **效力**：Phase 的划分与次序是计划；Phase 2 以后的 Wave 是**提议**，行数全部是估计，没有一个经过纵切验证。
> 每个 Phase 收尾时按实际行数回写，后面的 Wave 随之调整。

## 规则

| 规则 | 内容 |
| --- | --- |
| 编号 | `P<Phase>.W<Wave>`，例如 `P2.W3`。旧计划的 Wave（`D0–D8`、`T0–T7`）和认证线的 `C1–C6` 保留各自的含义，本文件在相应位置引用 |
| WIP=1 | 同一时间只做一个 Wave；判据没达到不开下一个（硬规则 3） |
| Wave 的大小 | 一个 Wave 是一组一起才有意义的功能块，做完能在 Lune 里演示或断言。核心行数多在 1–4k |
| 每个组件的第一个 Wave | 先写一页范围说明并做「第一刀」（`COMPONENTS.md`），再写其余部分；第一刀的实际行数偏离估计一倍以上就先停下重估 |
| 判据 | 每个 Wave 的判据都要落成可复现的命令（硬规则 6）；表里写的是判据的内容，命令在做的时候补 |
| 认证线 | 进认证范围的模块先有 LLR 再写码（I18），不单列 Wave，随所在 Wave 一起做 |
| 行数 | 「核心」是 `COMPONENTS.md` 里对应功能块之和；测试按该层的测试预算同比例估算，写在每个 Phase 的小计里 |

「累计」只含组件的核心与测试，到 Phase 6 为 271k。其余 29k 在 Phase 7 收口：集成层 9k、端到端与故障注入测试 8k、工具与示例 12k（门禁脚本等已有的部分计入其中）。集成层与工具实际上是前面各 Phase 随用随写的，这里没有逐 Wave 分摊。
仓库现有约 12k 行，其中 `Deuterium` 5.7k 与 `TritiumSQL` 0.9k 已计在各自 Wave 的行数里——那些 Wave 是在既有代码上改，不是从零写。

**依赖次序**：Phase 2 → 3 → 4 是硬次序（下层先于上层）。Phase 5 与 Phase 6 互不依赖，默认先 5 后 6；想先要内容引擎可以调换，但不能并行。

**可以停下来的地方**：每个 Phase 的出口都是一套可用的东西，不必一次承诺到 Phase 7。
