# Carbon 执行计划：Phase 与 Wave

> 总图是 `.plan/CARBON.md`，组件的功能块在 `.plan/COMPONENTS.md`；本文件回答「**按什么顺序做、每一步具体做什么、做完的标志是什么**」。
> 这是 Carbon 的唯一排期。
>
> **划分原则（用户 2026-11-14）：一个 Phase 只实现一个组件，一个 Wave 只实现一个功能。**
> 因此有 19 个组件 Phase（Phase 2–20），外加三个不属于任何组件的工程 Phase：0（骨架）、1（地基加固）、21（集成与发布）。
>
> **效力**：次序是计划；Phase 2 以后每个 Wave 的具体内容、接口名字与行数都是**提议**，没有一个经过实现验证。
> 接口名字只是示意，落地时以代码为准；每个 Phase 收尾时按实际情况回写本文件。

## 规则

| 规则 | 内容 |
| --- | --- |
| 编号 | `P<Phase>.W<Wave>`，例如 `P2.W3`。旧计划的 Wave（`D0–D8`、`T0–T7`）与认证线的 `C1–C6` 保留各自含义 |
| WIP=1 | 同一时间只做一个 Wave；判据没达到不开下一个（硬规则 3）。因此同一时间也只有一个 Phase 在进行 |
| 一个 Wave 一个功能 | 每个 Wave 交付一个可以单独说清楚、单独测试的功能。`COMPONENTS.md` 里较大的功能块被拆成多个 Wave，「功能块」列标明它属于哪一块 |
| 第一刀 ★ | 每个组件 Phase 里标 ★ 的 Wave 是该组件的纵切。做到它时如果累计行数偏离估计一倍以上，先停下重估本 Phase 再继续 |
| 判据 | 每个 Wave 的判据都要落成可复现的命令（硬规则 6）；表里写的是判据的内容，命令在做的时候补 |
| 每个 Wave 都带测试 | 判据里的用例随该 Wave 一起写，不单列测试 Wave；测试行数按该层的测试预算同比例估算 |
| 认证线 | 进认证范围的模块先有 LLR 再写码（I18），随所在 Wave 一起做 |
| Phase 的出口 | 除了表里写的出口，每个组件 Phase 还要满足总图 §3.3 的六条「做完」判据，并打版本 tag、回写预算 |
| 「迁移」与「接线」Wave | 不新增核心行数的 Wave：把既有代码改为使用新组件，或在 `Integration/` 里接端口。行数列记「—」 |
